Engine: `rusqlite` 0.40.2 with the `bundled` feature (SQLite compiled in).
File:   %APPDATA%\com.localassistant.app\assistant.db

--- PRAGMAS (database/mod.rs::Db::init, applied once at open) ---
PRAGMA journal_mode = WAL;        -- readers do not block the writer
PRAGMA foreign_keys = ON;         -- makes ON DELETE CASCADE in mcp_* and messages effective
PRAGMA synchronous = NORMAL;      -- safe under WAL, materially faster than FULL

--- MIGRATION MECHANISM (database/migrations.rs) ---
`PRAGMA user_version` holds the highest applied migration index.
Indices are 1-based and the array `MIGRATIONS: &[&str]` is APPEND-ONLY: a new
migration is added at the end, never edited in place. On open, every migration
whose 1-based index exceeds `user_version` is applied inside its own
transaction and then the version is stamped:

    for (i, sql) in MIGRATIONS.iter().enumerate() {
        let target = (i + 1) as i64;
        if version < target {
            conn.execute_batch(&format!("BEGIN; {sql}; PRAGMA user_version = {target}; COMMIT;"))?;
        }
    }

There are exactly 4 migrations. Verified distribution: 5 regular tables
(conversations, messages, settings, mcp_servers, mcp_tool_permissions) plus
dictation_history added later = 6, 1 FTS5 virtual table (messages_fts),
3 indexes, 3 triggers.

--- MIGRATION 1: initial schema (verbatim) ---

    CREATE TABLE conversations (
        id          TEXT PRIMARY KEY,
        title       TEXT NOT NULL,
        created_at  TEXT NOT NULL,
        updated_at  TEXT NOT NULL,
        model       TEXT,
        language    TEXT
    );
    CREATE INDEX idx_conversations_updated ON conversations(updated_at DESC);

    CREATE TABLE messages (
        id                 TEXT PRIMARY KEY,
        conversation_id    TEXT NOT NULL REFERENCES conversations(id) ON DELETE CASCADE,
        role               TEXT NOT NULL,
        content            TEXT NOT NULL,
        language           TEXT,
        reasoning          TEXT,
        sources_json       TEXT,
        tool_activity_json TEXT,
        tool_calls_json    TEXT,
        tool_call_id       TEXT,
        created_at         TEXT NOT NULL
    );
    CREATE INDEX idx_messages_conversation ON messages(conversation_id, created_at);

    CREATE VIRTUAL TABLE messages_fts USING fts5(
        content, conversation_id UNINDEXED, message_id UNINDEXED,
        tokenize = 'unicode61 remove_diacritics 2'
    );
    CREATE TRIGGER messages_ai AFTER INSERT ON messages
      WHEN new.role IN ('user', 'assistant') BEGIN
        INSERT INTO messages_fts(content, conversation_id, message_id)
        VALUES (new.content, new.conversation_id, new.id);
    END;
    CREATE TRIGGER messages_au AFTER UPDATE OF content ON messages BEGIN
        DELETE FROM messages_fts WHERE message_id = old.id;
        INSERT INTO messages_fts(content, conversation_id, message_id)
        SELECT new.content, new.conversation_id, new.id WHERE new.role IN ('user', 'assistant');
    END;
    CREATE TRIGGER messages_ad AFTER DELETE ON messages BEGIN
        DELETE FROM messages_fts WHERE message_id = old.id;
    END;

    CREATE TABLE settings (
        key   TEXT PRIMARY KEY,
        value TEXT NOT NULL
    );

    CREATE TABLE mcp_servers (
        id           TEXT PRIMARY KEY,
        name         TEXT NOT NULL,
        description  TEXT,
        transport    TEXT NOT NULL,
        command      TEXT,
        args_json    TEXT,
        env_json     TEXT,
        url          TEXT,
        headers_json TEXT,
        enabled      INTEGER NOT NULL DEFAULT 0,
        source       TEXT NOT NULL DEFAULT 'user',
        created_at   TEXT NOT NULL
    );

    CREATE TABLE mcp_tool_permissions (
        server_id  TEXT NOT NULL REFERENCES mcp_servers(id) ON DELETE CASCADE,
        tool_name  TEXT NOT NULL,
        permission TEXT NOT NULL,
        PRIMARY KEY (server_id, tool_name)
    );

--- messages_fts (FTS5 virtual table) ---
  column            indexed   notes
  content           yes       the message text; tokenize = 'unicode61 remove_diacritics 2'
  conversation_id    no       UNINDEXED, only carried for the JOIN back to conversations
  message_id         no       UNINDEXED, the join key used by the delete triggers

  The `remove_diacritics 2` option is why an Arabic or accented query matches
  unvocalised / unaccented input. Only roles in ('user','assistant') are
  indexed; `tool` rows are deliberately invisible to search.

--- 3 INDEXES ---
  idx_conversations_updated    ON conversations(updated_at DESC)
  idx_messages_conversation    ON messages(conversation_id, created_at)
  idx_dictation_history_created ON dictation_history(created_at DESC)

--- 3 TRIGGERS ---
  messages_ai  AFTER INSERT ON messages
               WHEN new.role IN ('user','assistant') -> insert into messages_fts
  messages_au  AFTER UPDATE OF content ON messages
               -> delete old row by message_id, re-insert only when the new role is indexed
  messages_ad  AFTER DELETE ON messages -> delete from messages_fts by message_id

--- SEARCH QUERY SHAPE (Db::search_conversations) ---
  Every whitespace-separated term is wrapped in double quotes (inner quotes
  doubled) so user input cannot inject FTS5 syntax. The FTS match and a title
  `LIKE ?2 ESCAPE '\'` (with `%`, `_` and `\` escaped) are UNION ALL'd, grouped
  by conversation id, ordered by MIN(pri) then `updated_at DESC`, and limited.
  `pri` is 0 for an FTS hit and 1 for a title-only hit, so content wins.
  An empty query short-circuits to `list_conversations(limit, 0)` with an
  empty snippet, so "" behaves exactly like "list everything".

--- IMPORT INVARIANT (Db::import_conversations) ---
  Every imported conversation receives a fresh UUID (an import can never
  overwrite existing data), the whole run is one transaction, only roles in
  ("user","assistant","assistant_tool_calls","tool") are inserted, and
  `attachments_json` is deliberately NOT imported because the files it points
  at live outside the bundle and the references would dangle.

--- NULLABILITY CONVENTION ---
The prevailing style is a REQUIRED property typed `| null`, not `?`.
`number | null` universally means "measure unknown / not loaded / unset"
(sizeBytes, maxContextLength, bubbleX/Y, overlayX/Y, latency-adjacent fields).
`apiKey: string | null` is never an empty string on the wire — `sanitize` turns
"" into `None` before saving.
Optional (`?`) properties are used only where the *stored column* may not
exist yet, so a pre-migration row still deserialises. There are exactly
THIRTEEN of them, and they are the ones `chatStore.messageToUi` has to guard
(`m.attachments ?? []`):
  Source.title, Source.  |  Message.reasoning, Message.sources,
  Message.toolActivity, Message.attachments, Message.stats  (5),
  MessageStats.tokensPerSecond, MessageStats.firstTokenMs,
  MessageStats.contextUsed, MessageStats.contextLength  (4),
  DictationStateEvent.text, DictationStateEvent.error, DictationStateEvent.result  (3)
The Rust side mirrors this with seven `#[serde(default)]` Option fields on
`database::conversations::Message`.

=== IPC WIRE FORMAT ===
================================================================================

--- Naming ---
  `#[serde(rename_all = "camelCase")]` on every payload struct crossing IPC.
  Struct *fields* become camelCase; struct *variant* names use a separate
  attribute where noted below. There is no `#[serde(rename_all = "snake_case")]`
  anywhere in the payload set except the deliberate exception in (3).

--- (1) ERROR SHAPE: { code, detail } ---
  `errors.rs` holds a private `WireError<'a> { code, detail }` and a
  hand-written `Serialize` that emits exactly:

      { "code": self.code(), "detail": self.to_string() }

  `detail` is the FULL Display string ("LM Studio error: connection refused"),
  never the raw inner payload. Every command returns
  `CmdResult<T> = Result<T, AppError>`, so a rejection reaches the frontend as
  a resolved `AppErrorPayload`; the frontend's `isAppError` / `toAppError` in
  `src/app/ipc.ts` recognise exactly this `{code, detail}` shape and map
  `errors.<code>` through `strings.en.json`.
  The 16 codes: lmstudio_unavailable, lmstudio_error, no_model, timeout,
  database, stt_unavailable, tts_unavailable, audio, mcp, permission_denied,
  download, not_found, invalid, io, cancelled, other.
  Documented divergence: AGENTS.md §3 asks for `Diagnostic{problem,cause,fix}`;
  the shipped wire format is `{code, detail}`.

--- (2) INTERNALLY TAGGED EVENT ENUMS: #[serde(tag = "type")] ---
  services::chat::orchestrator::ChatEvent
    #[serde(tag = "type", rename_all = "camelCase", rename_all_fields = "camelCase")]
  -> `{"type":"toolStarted", "turnId":..., "callId":..., ...}`
  services::chat::explain::ExplainEvent
    #[serde(tag = "type", rename_all = "camelCase", rename_all_fields = "camelCase")]
  -> `{"type":"delta","text":...}`
  services::stt::session::VoiceEvent  — tagged, payload keys stay snake_case on the wire
                                        and are camelCased by the TS union
  services::tts::TtsEvent             — tagged
  services::ai::ContentPart
    #[serde(tag = "type", rename_all = "snake_case")]
  -> `{"type":"text","text":...}` / `{"type":"image_url","image_url":{...}}`
  The `rename_all_fields` attribute is what makes `turnId` / `partialMessage` /
  `durationMs` appear inside a variant; without it the fields would stay
  snake_case. Dictation state events are NOT Rust enums — they are built as
  `serde_json::json!({ "state": ... })` objects.

--- (3) UNTAGGED ENUM: #[serde(untagged)] ---
  services::ai::MessageContent
    #[serde(untagged)] enum MessageContent { Text(String), Parts(Vec<ContentPart>) }
  A plain string body and a parts array are both valid; the receiver tries
  `Text` first. This is the only untagged enum in the crate.

--- (4) #[serde(default)] AND ITS EXACT USES ---
  * On 7 Option fields of `database::conversations::Message`: reasoning,
    sources, tool_activity, tool_calls, tool_call_id, attachments, stats —
    so a row written before migration 2 or 3 still deserialises.
  * At CONTAINER level (`#[serde(rename_all="camelCase", default)]`) on every
    `Settings` struct: a missing section or field falls back to `Default`.
    This is the single mechanism that lets an old settings blob keep loading
    after fields are added. `String::new()` values for new String fields come
    from the container `Default`, then `sanitize` replaces empty/invalid
    values with real defaults.
  * Per-field overrides: `#[serde(default = "default_true")]` on
    `SearchSettings::enabled` and `#[serde(default = "default_paste_as_file_chars")]`
    on `AiSettings::paste_as_file_chars` (2000), because the container default
    would be `false` / `0` and both are wrong for these fields.
  * `#[serde(default = "user_source")]` on `McpServerConfig::source` -> "user".
  * `#[serde(skip_serializing_if = "Option::is_none", default)]` on
    `ChatMessage::tool_calls` and `ChatMessage::tool_call_id`, so a request
    without tools omits the keys entirely instead of sending nulls.
  * `#[serde(skip)]` on `orchestrator::ReplyStats::generation_ms` — computed
    locally, never persisted or sent.
  * `#[serde(flatten)]` on `commands::voice::CatalogEntry::model`, so every
    `CatalogModel` field appears inline next to download_bytes / installed /
    recommended / downloading / deletable.
  * `#[serde(rename = "type")]` on `ToolDefinition::kind` and `sse::ToolCall::kind`
    (the OpenAI wire calls it `type`).
  * `#[serde(rename = "voiceEn")]` on `TtsSettings::legacy_voice_en` (and
    voiceAr / voiceDe): a legacy blob's key must be read exactly, while the
    container-level `rename_all` would otherwise have produced `legacyVoiceEn`.

--- (5) ENUM RENAME RULES ACTUALLY USED ---
  rename_all = "camelCase"    payload structs and event enums (the default choice)
  rename_all = "lowercase"    Permission, ToolCategory, ModelKind, AttachmentKind,
                              Lang, ExportFormat
  rename_all = "snake_case"   ContentPart only (matches the OpenAI content-part format)
  no attribute                VoiceEvent / TtsEvent variants and fields (camelCase by hand)
  Case-insensitive strings    `Permission` and `ModelKind` are read back from SQLite
                              through `serde_json::from_value` on a JSON string, so
                              a stored "Allow" or "Allow" variant still parses.

--- (6) STREAMING CHANNELS ---
  The two streaming commands are the ONLY place that does not use `app.emit`:
  they take a per-invocation `tauri::ipc::Channel<T>` as a parameter SIBLING of
  the payload object:
      chat_send(state, input: SendInput, on_event: Channel<ChatEvent>)
      chat_explain(state, id, selection, passage, on_event: Channel<ExplainEvent>)
  The frontend constructs `new Channel<T>()`, assigns `onmessage`, and passes
  it as `{ input, onEvent: channel }`. `Channel::send` is a no-throw,
  best-effort push: a dropped chunk never fails the turn. Both commands always
  return `Ok(())`; errors arrive as a `type:"error"` event instead.

--- (7) ARGUMENT NAMING ---
  Tauri 2 converts Rust snake_case parameter names to camelCase on the JS side,
  so `attach_files(paths)` becomes `invoke("attach_files", { paths })` and
  `mcp_set_permission(server_id, tool, permission)` becomes
  `invoke("mcp_set_permission", { serverId, tool, permission })`.
  `Option<T>` parameters may be omitted or passed as `null`; the frontend passes
  `undefined`/`null` for them (e.g. `{ url, apiKey, provider }`).

=== ENCRYPTED BACKUP FORMAT ===
================================================================================

Signature: `LAIA-BK1`  (settings/backup.rs)

  offset  size  content
  0       8     magic  b"LAIA-BK1"  (file signature + format version)
  8       12    nonce  ChaCha20Poly1305 random nonce from OsRng
  20      N     sealed ChaCha20-Poly1305 ciphertext of the Settings JSON,
                   including the 16-byte Poly1305 authentication tag

  total length = 8 + 12 + (plaintext_len + 16)

Key derivation:
  KEY_SEED = b"local-ai-assistant/settings-backup/v1/7c1e9a42f0d84b6b"
  key      = SHA-256(KEY_SEED)  ->  32 bytes  ->  ChaCha20Poly1305::new(key)

  The seed is HARD-CODED and compiled into the binary. This protects a backup
  that is copied around or opened by accident and makes the file tamper-evident,
  but it is not a secret: anyone who extracts the key from the binary can
  decrypt it. Changing the seed makes every previously written backup
  unreadable, which is why it carries a `/v1/` segment and a fixed hex suffix.

Plaintext: `serde_json::to_vec(&Settings)` — the complete settings document,
camelCase, no encryption of any inner field. API keys are included ONLY when
the user ticks "include keys" in the export dialog; otherwise
`backup::strip_keys` blanks `ai.api_key` and every
`ai.providerProfiles[*].api_key` before encryption.

Decrypt failure modes (all the same message, so no oracle):
  wrong magic, truncated body (<= 12 bytes after the magic), authentication
  failure (tampered or damaged), or unparseable JSON
  -> AppError::Invalid("this is not an Open Local Assistant settings backup, or it was damaged")

Import merge (`merge_import`), i.e. what an imported backup may NOT change:
  version                        <- kept from the current settings
  lastConversationId             <- kept
  general.firstRunComplete       <- kept
  general.window                 <- kept (this machine's window placement)
  general.bubbleX / bubbleY      <- kept
  dictation.overlayX / overlayY  <- kept
  any API key missing from the backup keeps its current value
  everything else is taken from the backup, then `sanitize()` runs on the result.

Related but separate format — the conversation export bundle:
  `ExportBundle` is PLAIN JSON (not encrypted), `format = "local-assistant-conversations"`,
  `version = 1`. Markdown and TXT exports are plain text.

--- HUGGING FACE CACHE LAYOUT THE SCANNER UNDERSTANDS ---
`services::models::ModelStore::scan_dir` recurses to MAX_DEPTH = 4 and treats
any folder recognised by `detect_custom` as a LEAF. It therefore works
unmodified on three layouts:

  1. flat              <extra-dir>\<model-folder>\
  2. grouped            <extra-dir>\<publisher>\<model-folder>\
  3. Hugging Face cache <cache-root>\models--<org>--<name>\snapshots\<commit-hash>\
       e.g.  models--k2-fsa--kitten-nano\snapshots\abc123\
             models--Qwen--Qwen3-TTS-12Hz-0.6B-Base\snapshots\def456\

  `display_name` rewrites layout 3 to a friendly name: when the parent folder
  is literally `snapshots`, the grandparent `models--<org>--<name>` is
  converted to `<org>/<name>` (`--` becomes `/`); anything else falls back to
  the folder's own name.
  Folders that must be skipped while walking: `.git`, `blobs`, `refs`, `dict`,
  `node_modules`, `espeak-ng-data`, `test_wavs`, and any dot-entry.
  At depth 0, a child whose name matches a catalogue id is skipped when the
  catalogue copy is already known, so the same model is not listed twice;
  the final merge deduplicates strictly BY PATH.
  `incompatible()` scans extra folders only, aborting at depth > 4 or after
  50 findings.

--- SECURITY NOTES ON STORED DATA ---
  * API keys live in the `settings` table, not in the OS keyring, despite
    what PRIVACY.md and the architecture table imply; the `windows` crate's
    `Security_Credentials_UI` feature is used only for the Windows Hello
    consent prompt in `desktop/verify.rs`.
  * MCP server `env_json` / `headers_json` hold user-supplied secrets; the
    import preview exposes key NAMES only.
  * The voice/Speech model downloads are the only inbound files, and every
    one is SHA-256 verified before it is committed to the models folder.
  * Logs contain no conversation content unless
    `general.logConversationContent` is explicitly turned on.
